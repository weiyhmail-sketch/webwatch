我用 AI 给自己写了个 IBKR Web Trader——替代官方繁琐 UI，4 天 7680 行代码 259 个测试全绿

IBKR Web Trader —— 连接 IBKR 的可视化交易客户端，替代官方桌面 / 移动端繁琐 UI，把我自己的交易习惯都注入进去。这是我第一个公开项目，不是 demo，是拿真金白银交易的生产系统。

为什么要做这个：IBKR 官方 UI 真的太繁琐

我做美股超短线——买入后涨 0.2% 就卖，靠速度和纪律赚手续费差价。

盈亏空间极小，对下单工具的要求就变得极高：

  • 快——看到机会，两秒内必须下单完成
  • 准——止盈止损必须自动挂好，不能靠人盯盘
  • 安全——任何情况下都不能出现"买了但没挂保护"的裸仓

但 IBKR（盈透证券）官方提供的两套客户端都跟"快"反着来：

  • TWS 桌面端——功能强大，但操作路径太长：查报价 → 切到下单 → 填表 → 提交 → 切到持仓页 → 手动挂止盈 → 手动挂止损……一套下来超短线机会早就跑了
  • IBKR 移动端——按钮密集、信息塞满屏、误触风险高，盘中手抖一下就是事故

这两套都是 IBKR 给"通用交易者"做的——要兼顾日内、波段、期权、期货所有人，所以路径长、菜单深、按钮多。但我只做自己的超短线，每天用的功能就那七八个。剩下的菜单只会拖慢我。

我需要的不是另一个通用客户端，而是一个按我自己的交易习惯定制的轻量 web 客户端：输入股票代码，点一下按钮，买入单和止盈止损单同时出去——这就是IBKR Web Trader。

它长什么样

一句话：连接 IBKR 的可视化交易客户端，全 web 实现，浏览器打开即用。

深色专业交易终端风格，左右分栏——左边常驻下单区（无需切页面），右边实时行情看盘。所有信息一屏到底，鼠标键盘混用都顺手。

上面这个动图展示了核心下单流程：

点击报价行 → 大号行情自动展示 → 限价自动填入 → 调整数量 → 预览计算结果

底部预览结果一目了然：止盈 293.56 / 止损 291.79 / 金额 14,648.50 / 扣费净盈亏 28.80。一切算好了，你只需要决定——买不买。

点"买入·限价"，系统把入场单、止盈单、止损单三单同发，零空窗。涨到位自动卖，跌到位自动止损。

做多做空一键切换

  • 做多：红色按钮"买入·限价"/"买入·市价"——买低卖高
  • 做空：绿色按钮"卖空·限价"/"卖空·市价"——卖高买低

切换方向后，止盈止损自动反转（做空时止盈在下方、止损在上方），确认弹窗的动词也随之变化。

止盈止损：三种方式按你的习惯来

超短线交易者的思维方式不一样——有人按百分比想（"涨 0.2% 就卖"），有人按股价增减想（"涨 1 块钱就走"），有人按盈利金额想（"赚 100 美元收手"）。IBKR Web Trader 三种都支持，止盈止损各自下拉一切换即可——这就是"按自己交易习惯定制"的具体体现：不强迫你用某一种范式。

方式 输入 止盈价 扣费净盈亏
百分比0.2 %$294.19+$28.80
股价增减+$1.0 / 股$294.60+$49.30
盈利金额$100$295.60+$99.30

止损同理也是三选一，止盈和止损可以混用不同方式——比如止盈用百分比、止损用股价增减完全 OK。预览底部还显示"扣费净盈亏"——双向佣金已经算进去，达到止盈价你真正能落袋多少，肉眼可见。

异动雷达：发现正在暴动的股票

右栏切到"异动雷达"标签，系统每 25 秒扫描全市场，把正在剧烈波动的股票实时呈现：

急拉榜 —— 正在快速上涨的股票。上面的动图中 GLXG 日内涨幅 +181%、GELS +290%、PPCB +273%，都是盘中的极端异动。

急跌榜 —— 正在快速下跌的股票。做空机会一目了然。

事件流 —— 底部实时滚动，"1分钟 +3.34% 急动"、"5分钟连续拉升"、"放量 2489x"、"突破日内高点"……每一条都是实时发生的市场信号。

看到感兴趣的股票？点一下那行，左侧下单区自动填入代码和价格——从发现到下单，路径最短。

指标 含义

所有指标都是纯函数计算，不依赖外部服务，45 个单元测试覆盖。

不止是一个下单面板

除了核心下单功能，面板还提供完整的交易工作台：

实时报价看板 —— 自选股列表实时推送买一/卖一/最新价/涨跌幅，WebSocket 每 300ms 刷新。

持仓监控 —— 实时展示当前持仓的代码、方向、数量、均价。

挂单追踪 —— 当前未成交的限价单/止盈止损单一目了然。

今日成交记录 —— 每笔交易的时间、代码、类型、成交价、状态（Filled/Cancelled），完整复盘。

风控护栏 —— 下单前自动检查：单笔亏损不超过 0.5% 净值（BLOCK）、金额不超过购买力（BLOCK）、PDT 规则提示（WARN）。超限直接拒单，不会下出去。

键盘热键 —— b=市价买入 / l=限价买入 / f=全平 / c=撤单。手在键盘上不用动鼠标。

顶部控制栏：账户、时段、紧急一栏掌控

超短线的关键信息必须一眼能看到。IBKR Web Trader 把账户状态、交易时段、盈亏和应急按钮全压在顶部一栏：

① 24 小时识时段：盘前 / 盘中 / 盘后 / 夜盘

绿色「常规盘」徽章不会一直绿。系统按美东时间（ET）自动识别当前所处时段：

  • 常规盘（绿色徽章）—— 09:30–16:00 ET，最活跃
  • 盘前（琥珀色徽章）—— 04:00–09:30 ET，财报后异动常发时段
  • 盘后（琥珀色徽章）—— 16:00–20:00 ET，盘后财报释放
  • 夜盘（琥珀色徽章）—— 20:00–次日 04:00 ET，国内交易者的友好时区
  • 休市（灰色徽章）—— 周末或节假日

非常规盘下单时，系统自动启用 outsideRth=True，市价单自动转激进限价（避免远离价的成交），止损自动转 stop-limit（盘前盘后流动性差时防止滑出大缺口）。盘前、盘后、夜盘全部都能下单，无需切换任何设置。

② 盈亏一眼看清：今日 = 已实现 + 浮动

顶栏的盈亏数字拆得很细：

  • 今日盈亏 —— 当日全口径盈亏，红涨绿跌（A 股惯例）
  • 已实现 —— 当日已平仓的累计盈亏（手续费已扣）
  • 浮动 —— 当前持仓的未平盈亏（按现价计算）

超短线追求小赚多次，「已实现」才是真金白银落袋数字；「浮动」提醒你当前持仓的状态。两个数字并排显示，决策时无需切回经纪商主界面。

③ 紧急按钮：极端情况下一键全平 / 全撤

行情突变时（重大新闻、闪崩、突发停牌），最重要的是立刻清空风险。顶栏右侧常驻两个按钮：

市价全平（绿色按钮） —— 把所有持仓按市价一次性平掉。多头变卖出、空头变买入，分批同发。热键 f。

撤全部挂单 —— 把当前所有未成交的限价单 / 止盈止损单撤掉。常用于"我不想再 mess with this 了"的时刻。热键 c。

两个按钮都有二次确认弹窗（防止误触），但点确认后立即执行，不会等任何上下文。"快"是这里的唯一指标——别让一次犹豫吞掉你一整天的盈利。

安全：真金白银的底线

5 条红线

  1. 绝不未经确认连接实盘
  2. 绝不改下单逻辑而不写测试
  3. 绝不让保护单缺失（裸仓 = 最危险的状态）
  4. 绝不降低测试覆盖
  5. 绝不让密钥进入代码仓库

裸仓防御

"裸仓"——买了股票但止盈止损没挂上——是超短线最致命的风险。

系统对这个问题做了四层防御：

第 1 层：限价买入用原生 bracket order，三单原子下发，零空窗

第 2 层：市价买入成交后立即挂 OCA 保护，实时验证是否挂活

第 3 层：保护单失败？立即市价平仓，宁可不赚也不裸仓

第 4 层：紧急平仓也验证成交，没平掉就强制告警

模拟盘优先

默认连接模拟盘。切实盘需要两把钥匙同时打开——缺任何一个，自动回退模拟盘。实盘模式下顶部有红色脉冲横幅，每笔下单额外弹窗确认，首周还有单笔金额上限。

3 轮对抗性安全审计

写完代码不算完——我让 Claude Code 生成复核包（review bundle），交给 ChatGPT 做对抗性审计。

三轮下来，每轮都抓到了真的 P0 级 bug：

第 1 轮（自查）：发现 5 个 P0 —— NaN 绕过风控护栏、目标过大算出负保护价、入场超时静默当未成交、保护单瞬态误判、并发下单无锁。

第 2 轮（ChatGPT 审计）：发现止盈成交后 OCA 撤掉兄弟止损腿，系统误判为"保护单异常"→ 触发紧急平仓 → 对已平仓位反向下单 = 开反向裸仓。这恰是"+0.2% 快速止盈"的高频路径。

第 3 轮（复核修复的复核）：发现持仓缓存延迟导致紧急平仓读到 0 → 跳过平仓 → 谎报已平，真实持仓裸仓。

这些 bug 不跑真钱可能永远不知道。但通过对抗性复核，上线前就堵死了。

开发方式：人 + 双 AI 协作

这个项目绝大部分代码是 AI 写的。

我用 Claude Code（Anthropic 的 CLI 编程工具）作为主力开发者，ChatGPT 作为独立复核方。三方各司其职：

角色 职责
我需求决策、验证、运行、批准上线
Claude Code架构设计、写代码、调试、code review
ChatGPT通用工具教学 + 下单链路对抗性复核

它不是"帮你写几行代码"

Claude Code 不是 Copilot 那种补全工具。它是一个能理解整个项目上下文的开发者。

我给它写了一份 CLAUDE.md（协作说明），定义了 5 条红线、代码风格、开发流程、什么时候必须停下来问我。它按这个规则工作。

每个 session 开始，它先读 STATUS.md（进度交接文件），知道做到哪了、哪些决策已锁定、下一步是什么。session 结束时更新这个文件，下次接着来。跨 session 的上下文，完全不需要我重复交代。

强制 TDD

下单链路的核心模块（pricing / broker / order_service），规则是先写测试，再写实现。不是建议，是红线。改一行计算逻辑都必须先有对应的测试用例。

这保证了 259 个测试不是装饰品，而是每一个都对应一个真实的业务分支。
